# Codex decisions

## 2026-11-15

- **Snapshot the existing working tree before edits.** Alternatives: copy all directories or omit bulky/generated directories. Chosen: a tar snapshot excluding dependency caches, build output, previous backups, archive, and `.git`, as requested. This captures source and configuration without recursive snapshots.
- **Do not run Git commands.** Alternatives: inspect Git state as a standard orientation step. Chosen: filesystem inspection and direct command outputs only, following the owner’s explicit instruction.
- **Do not make a database dump.** `pg_dump` is unavailable and the checked-in Alembic configuration and project docs show SQLite. Alternatives: attempt to treat SQLite as PostgreSQL or copy the live DB. Chosen: leave data untouched and record that a DB backup tool was unavailable; the project snapshot excludes no live DB files.
- **Scope test and lint commands to active source directories.** Alternatives: scan the whole repository. Chosen: avoid backup/archive copies causing duplicate test collection and irrelevant lint output.
- **Make migration 0006 downgrade conditional.** The prior downgrade always raised, so it could never roll back even when no legacy NULL values existed. The updated downgrade restores NOT NULL only after checking that no rows would be rejected. Alternatives: fabricate timestamps or discard the rows; rejected because both rewrite/drop data. Full-chain rollback is still blocked by an independent `0004` SQLite index-ordering error.
- **Run database/application work on a scratch DB when possible.** The configured local SQLite database is readonly in this execution context, and application startup attempted a provenance backfill. Chosen: stop using that DB and use `/tmp` scratch SQLite for migration/startup checks; never change permissions or data to get past the error.
- **Move the three stale demo buses by appending simulator telemetry, never rewriting their Chennai history.** The browser-facing API process had `/tmp/opencode/audit_live_copy.db` open. Appended rows generated by `simulated_telemetry()` around the configured HKBK origin, marked `simulated=true` and `data_source=simulator`; retained all earlier rows. Alternatives were rewriting old fixes, deleting legacy vehicles, or guessing a receiver protocol; rejected because history must remain intact and no hardware exists. The API and in-app tracking page then showed all three near Bengaluru.

## 2026-11-16

- **Publish three private repositories from the current working tree snapshot.** Created and pushed `CorbenZen/NavIC-complete` (initial commit `17e67ec`, 338 files), `CorbenZen/NavIC-backend` (`59638e6`, 209 files), and `CorbenZen/NavIC-frontend` (`f5fe3cf`, 127 files). `gh repo view` reported all three as private with `main` as the default branch. The exports are under `/tmp/navic_github_exports_20261116_01`; new repos start with a snapshot commit and do not copy the source repository's earlier commit history.
- **Wait for GitHub CLI authentication instead of handling credentials.** The first `gh auth status` call reported the cached account token invalid and the restricted shell could not reach GitHub. The owner authorized a device login; after that flow completed, an escalated `gh auth status` reported a valid `CorbenZen` session with `repo` scope. No token value was recorded.
- **Exclude local data and tool state from the GitHub snapshots.** The copy excluded `.env`, SQLite databases, backups, virtual environments, `node_modules`, caches and built frontend output. The credential-pattern scan reported no local `.env` files or recognized private-key/GitHub/AWS/Slack/Resend tokens. All other current source edits and deletions were preserved as they stood in the working tree.
- **Keep the extracted frontend runnable from its repository root.** The original Vite config resolves the project root one directory above `frontend/`; the frontend-only export changes that one relative root expression because `frontend/` becomes the repository root. `npm run check` in the exported frontend completed lint and build, with the same 35 lint warnings and standard bundle warnings as the source tree.

## 2026-11-25

- **Deploy as one Render Docker service plus managed PostgreSQL.** FastAPI already serves the built SPA same-origin, so one service carries UI, REST and WebSocket. Alternatives: static frontend host plus separate API (two origins, more CORS/cookie surface) or serverless (cannot hold WebSockets). Files: `Dockerfile`, `.dockerignore`, `render.yaml`, `scripts/render_start.sh`, guide in `docs/DEPLOY_RENDER.md`.
- **Add runtime dependency `psycopg[binary]`.** `navic_tcp/db.py` normalizes Postgres URLs to the `postgresql+psycopg` driver and production validation requires PostgreSQL, but no driver was listed, so a Postgres deploy could not start.
- **Build the frontend on Node 26 in Docker.** `npm ci` on Node 22/npm 10 fails with ERESOLVE on the existing `@eslint/js@10` vs `eslint@9` peer range; Node 26/npm 11 matches the local toolchain. The lint-dependency mismatch itself is unchanged and still worth fixing.
- **Disable TCP and enable in-app demo simulation on Render.** Render exposes HTTP(S) only; telemetry stays labelled simulated. No hardware behaviour was invented.
- **Verified with Podman against a throwaway `postgres:17`.** Migrations 0001→0008 applied on a fresh database, idempotent seed, clean restart, health/meta 200, protected routes 401, sign-in page rendered. Test secrets were generated per run and deleted with the containers.

## 2026-11-26

- **Demo simulation now reads the configured `DEVICE_REGISTRY`.** `DemoSimulation._get_demo_devices` hardcoded `config/devices.json` (3 `SIM-*` devices), while the server, the seed and the TCP simulator use `config/devices.demo.json` (`IVTD_BUS_01-06`). On Render every simulated fix was dropped as "telemetry for unknown device", so the map stayed empty. Fixed to `os.getenv("DEVICE_REGISTRY", DEFAULT_REGISTRY_PATH)`, matching `fastapi_app.registry`; `render.yaml` sets `DEVICE_REGISTRY=config/devices.demo.json` explicitly. Regression tests: `backend/tests/test_demo_simulation.py`. Verified in a production-mode container against `postgres:17`: 6 `IVTD_BUS_*` devices, 13 persisted fixes each, 0 unknown-device warnings, `/api/tracking/latest` returned all six with `simulated: true`.
- **Added `scripts/make_admin_hash.py`.** Generates `ADMIN_PASSWORD_HASH` with a confirm prompt; `--show` echoes input for terminals where hidden typing was confusing. Prints only the hash.
- **Display status freshness follows provenance.** REST/UI status (`/api/tracking/latest`, bus listing, dashboard counts, device latest) used a fixed 5-minute window, while the live demo path used 20 s, so a refreshed page showed a stopped simulation as "Stopped" for up to 5 minutes. Added `vehicle_status.freshness_for_source` (simulator: 20 s, hardware/unknown: 5 min) and `fastapi_app._display_status`. The offline-alert loop intentionally keeps 5 minutes so the demo's 25-second outage phase does not raise device-offline alerts every cycle. Tests: `DisplayFreshnessBySourceTests`. Verified in a production container on `postgres:17`: Stopped right after stop, Out Of N/w 25 s later on refresh.
